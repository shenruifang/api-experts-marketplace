# 原料药立项评估团（API Project Evaluation Team）

一个面向原料药（API）项目的立项评估专家团，用于 WorkBuddy。方法论底座为**五维决策模型 + 阶段门流程**，由 1 位主理人调度 9 位专业角色协同输出立项结论。

> 本仓库为**精简公开版**：包含完整的方法论框架与团队协作机制，不含任何企业内部数据、客户信息或未公开资料。

---

## 它能做什么

把一句模糊的诉求——"我们缺品种"、"这个原料药能不能做"、"下个月立项会报什么"——放进一套有纪律的流程里，输出能直接上决策门的文档。

**典型用法**

```
评估 XX 原料药的立项可行性，输出完整立项评估报告
帮我筛选适合我们产线的原料药品种，输出优先级立项清单
对比 XX 原料药的两条合成路线，量化成本、放大风险与 EHS 代价
我们的设备能不能做 XX？沉默期资金撑不撑得住？
XX 原料药卖给谁？多久能产生收入？
```

单一维度的问题由主理人直调对应角色，不启动完整流程。

## 方法论要点

### 五维决策模型（交集关系，非加权求和）

```
立项可行性 = F(市场窗口, 成本竞争力, 质量合规, 供应链可靠, 自身能力)
```

**是交集，不是加权平均。** 任一维度的严重短板都足以使项目在整体上失去可行性。核心任务不是孤立追求某维最优，而是在识别各维硬性红线之后，寻找一个可接受的组合解。

### 三种竞争形态

| 形态 | 竞争核心 | 评估侧重 |
|------|---------|---------|
| 专利药原料药及中间体 | 技术能力 + 质量体系 | 重工艺与质量，成本从轻；须评估专利到期后的需求断崖 |
| 首仿及专利后期原研 | **速度** | 重专利时序、注册节奏、设备改造周期与窗口的赛跑 |
| 无专利成熟品种 | **成本** | 重全成本模型、规模效应、供应链管理 |

形态判定错误会导致整套评估跑偏。

### 阶段门流程

| 阶段 | 核心问题 | 投入 | 输出物 |
|------|---------|------|-------|
| 0 初筛 | 有什么明显不行的？ | 极低 | 候选清单 + 一页纸初筛表 |
| 1 预调研 | 窗口是否存在？ | 低 | 调研报告 + Go/No-Go |
| 2 深度调研 | 能不能赚钱？ | 中 | 立项报告 |
| 3 决策门 | 大家是否一致同意？ | 低 | 决议书（Go / Kill / Recycle / Hold） |
| 4 动态复审 | 是否还值得继续？ | 持续监控 | 复审报告 |

价值在于**花小钱淘汰、花大钱验证**。严禁跳过前序阶段直接进入深度调研。

### 决策门定量阈值

| 指标 | 否决线 | 通过线 |
|------|-------|-------|
| NPV | ＜0 | ＞0 且 IRR＞WACC |
| IRR（税后全投资） | ＜12% | ＞18% |
| 投资回收期（含建设期） | ＞8 年 | ＜6 年 |
| 盈亏平衡点（产能利用率） | ＞60% | ＜50% |
| 安全边际率 | ＜15% | ＞30% |

### 初筛一票否决链

1. **市场窗口粗判**：年需求量数量级 + CDE 备案家数与 A 状态数
2. **自身设备硬约束**：以**现有设备**为准，不是"可改造设备"；改造超 18 个月而窗口不足 2 年直接排除
3. **成本数量级**：预估物料成本超市场可接受价格的一半且无明显收率/回收优势 → 不可行

### 研发三报告

| 文档 | 回答 | 对应阶段 | 结论形式 |
|------|------|---------|---------|
| 项目调研报告 | 能不能做 | 第 1 阶段 | 推荐立项 / 暂缓跟踪 / 果断放弃 |
| 项目立项报告 | 值不值得做 | 第 2 阶段 | 批准立项 / 有条件批准 / 否决 |
| 项目开题报告 | 具体怎么做 | 立项批准后 | 方案科学合规可控，可进实验室 |

## 安装

### 方式 A：添加为市场源（推荐）

1. 到 [Releases](../../releases) 下载最新版的 `api-experts-marketplace-vX.X.zip`
2. 在 WorkBuddy 的插件 / 专家市场管理页，**添加市场源**，填入该 zip 的下载直链
3. 添加成功后即可在市场列表中搜索到并安装「原料药立项评估团」

> 源支持自动更新：本仓库发布新版本后，已添加该源的用户会自动拉取新版。

### 方式 B：手动安装

1. 下载并解压 `api-experts-marketplace-vX.X.zip`
2. 把 `api-experts-marketplace/plugins/api-project-evaluation/` 整个目录复制到：
   - Windows：`C:\Users\<用户名>\.workbuddy\plugins\marketplaces\my-experts\plugins\`
   - macOS / Linux：`~/.workbuddy/plugins/marketplaces/my-experts/plugins/`
3. 在该机器上执行（脚本位于 WorkBuddy 的 `expert-manager` skill 目录下）：

   ```bash
   python3 scripts/register_expert.py <专家目录的完整路径>
   ```

4. 重启 WorkBuddy，在「专家中心 → 我的专家」中即可看到

## 数据纪律

- 所有收率、成本、价格、专利到期日、需求量、供应商与客户信息必须标注来源与检索日期，查不到写「未获取」
- **严禁编造**
- 收率须区分文献收率 / 专利收率 / 小试实测收率
- 未取得用户确认的企业数据前，设备、产能、团队、资金结论一律标「待企业确认」
- 每次交付须附：假设清单、待补充清单（标注责任方）、数据来源与检索日期总表
